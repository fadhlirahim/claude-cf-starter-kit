# Project: [App Name]

> A Cloudflare-native fullstack TypeScript application built with TanStack Start (on Workers), better-auth, Drizzle ORM on D1, server functions, Workers AI through AI Gateway, R2, Workflows, Scheduler, and Email Sending.

## Tech Stack

| Layer | Technology | Notes |
|-------|-----------|-------|
| Runtime | Cloudflare Workers (Workers Static Assets) | No Node, no Pages — Workers only |
| Framework | TanStack Start (Vite + `@cloudflare/vite-plugin`) | SSR streamed from the Worker |
| Routing | TanStack Router (file-based) | tanstack.com/router |
| Data fetching | TanStack Query | tanstack.com/query |
| API | TanStack Start server functions (`createServerFn`) + Zod 4 | No tRPC — server fns are native to Start |
| Forms | TanStack Form + Zod 4 | tanstack.com/form |
| Auth | better-auth (Drizzle adapter, D1) | better-auth.com |
| Database | Drizzle ORM + Cloudflare D1 (SQLite) | orm.drizzle.team |
| Storage | Cloudflare R2 | bucket binding, signed URLs |
| Async | Cloudflare Workflows | `WorkflowEntrypoint` class per workflow |
| Cron | wrangler `triggers.crons` + `scheduled` handler | dispatch by `event.cron` |
| Email | Cloudflare Email Sending (`send_email` binding) | DKIM/SPF/DMARC managed by CF |
| AI | Workers AI binding via AI Gateway | also fronts `@ai-sdk/openai`, `@ai-sdk/google` |
| UI | shadcn/ui (new-york), Tailwind v4, lucide | components.json drives shadcn CLI |
| Validation | Zod 4 (import from `zod/v4`) | zod.dev |
| Linting/format | Biome | biomejs.dev |
| Test | vitest + `@cloudflare/vitest-pool-workers` | bindings via Miniflare |
| Package manager | bun | bun.sh |

## Coding Conventions

### General

- `function` declarations for components and server functions; `const` arrow for utilities.
- Named exports only (route files and config files are the only exception — see `biome.json` overrides).
- Strict TypeScript. No `any`, no `as` casts unless provably safe.
- Files: kebab-case. Types: PascalCase. Functions: camelCase.
- Collocate code; don't build deep folder hierarchies before they're earned.

### TanStack Start (Cloudflare flavor)

- IMPORTANT: `getRouter()` in `src/router.tsx` MUST return a NEW router instance per call. SSR isolates per request — a shared instance leaks state across users.
- IMPORTANT: Vite plugin order is `tailwindcss()`, `tsconfigPaths()`, `cloudflare()`, `tanstackStart()`, `viteReact()`. The Cloudflare plugin must run before `tanstackStart()` so the Worker environment is set up before Start binds its handlers.
- `compatibility_flags: ["nodejs_compat"]` is required in `wrangler.jsonc` — without it, packages that pull `node:*` polyfills (Drizzle, better-auth) fail at deploy.
- The Worker entry is `src/entry.server.ts`. It exports a default object with `fetch` and (optionally) `scheduled`, plus named Workflow class exports.
- Route loaders run on BOTH client and server. For anything Worker-only (env bindings, secrets, D1, R2, AI), use `createServerFn`.
- Server functions are the API layer — there is no tRPC in this stack.

### TanStack Start Server Functions (the API layer)

- Define in any server-side module; commonly under `src/server/...` or co-located with the route in `src/routes/api/...`.
- IMPORTANT: All input validation goes through Zod 4. Use `.inputValidator(zodSchema)` so the handler receives a parsed, typed `data`.
- Access bindings via `import { env } from 'cloudflare:workers'`. Never import this from a route component — it'll bundle the worker module into the client.
- For auth: use a server-fn middleware that calls `auth.api.getSession({ headers: getRequestHeaders() })` and rejects when missing.
- Throw plain `Error` for failures; the framework serializes them. For typed error codes, return a Result-like discriminated union.
- Consume from React Query: `useQuery({ queryKey: ['feature', id], queryFn: () => myServerFn({ data: { id } }) })`. Mutations: `useMutation({ mutationFn: myServerFn })` followed by `queryClient.invalidateQueries({ queryKey: [...] })`.

```ts
// src/server/services/get-post.server.ts
import { createServerFn } from '@tanstack/react-start'
import { env } from 'cloudflare:workers'
import { z } from 'zod/v4'
import { createDb } from '../db'

const Input = z.object({ id: z.uuid() })

export const getPost = createServerFn({ method: 'GET' })
  .inputValidator(Input)
  .handler(async ({ data }) => {
    const db = createDb(env.DB)
    return db.query.post.findFirst({ where: (p, { eq }) => eq(p.id, data.id) })
  })
```

### TanStack Router

- File-based only. Never edit `routeTree.gen.ts`.
- `__root.tsx` (root), `$param.tsx` (dynamic), `_layout.tsx` (pathless), `(group)/` (organizational).
- Validate search params with `zodValidator` from `@tanstack/zod-adapter` and ALWAYS wrap with `fallback()` so invalid URLs render gracefully.
- Loader vs `beforeLoad`: loader for data prefetching, `beforeLoad` for auth guards and context augmentation.
- Use `notFound()` from `@tanstack/react-router` to throw 404s in loaders.

### Cloudflare Bindings — Access Pattern

- Bindings (D1, R2, KV, AI, Workflows, Email, Service) are typed via `worker-configuration.d.ts`. Regenerate with `bun cf-typegen` after editing `wrangler.jsonc`.
- IMPORTANT: Read bindings via `import { env } from 'cloudflare:workers'` — NOT `process.env`. Anything in `wrangler.jsonc` `vars` and any secret set via `wrangler secret put` lives on `env`.
- Binding access on the type-level: `env.DB` (D1Database), `env.AI` (Ai), `env.MY_BUCKET` (R2Bucket), `env.SEND_EMAIL` (SendEmail), `env.MY_WORKFLOW` (Workflow).
- Pure helpers should accept the binding as an argument: `function send(db: D1Database, ...)`. The `cloudflare:workers` import only at the top of the call chain (route handlers, server fns, scheduled handler).
- Local dev: `.dev.vars` (key=value lines). Prod: `wrangler secret put NAME` or set in the dashboard.

### Drizzle ORM on D1

- Schema in `src/server/db/schema.ts`. SQLite types: `text`, `integer`, `real`, `blob`. Booleans: `integer({ mode: 'boolean' })`. Timestamps: `integer({ mode: 'timestamp' })`.
- DB factory: `createDb(d1: D1Database)` returns `drizzle(d1, { schema })`. Always per-request, never module-scoped.
- Use the relational query builder (`db.query.<table>.findFirst/findMany`) for reads. Define `relations()` even when only `experimental: { joins: true }` is enabled (better-auth's Drizzle adapter benefits 2-3x).
- Migrations: `bun db:generate` reads schema → writes SQL. Apply: `bun db:migrate:local` (Miniflare D1) or `bun db:migrate:remote` (live D1).
- Use `$inferSelect` / `$inferInsert` for row types. Don't hand-write Row types.
- IMPORTANT: D1 has no `psql`/`mysql` interactive shell. For ad-hoc queries: `wrangler d1 execute DB --local --command "SELECT ..."`. Avoid `--remote` without an explicit reason.
- IMPORTANT: D1 transactions are LIMITED — `db.transaction(...)` runs as a batched D1 transaction. Don't expect Postgres-level isolation.

### better-auth on D1

- Single `createAuth(d1)` factory in `src/server/auth.ts`. Plugin chain: domain plugins (admin, organization, …) THEN `tanstackStartCookies()` LAST.
- The secret comes from a CF secret, not from `wrangler.jsonc` vars: `(env as unknown as Record<string, string>).BETTER_AUTH_SECRET`. Set with `wrangler secret put BETTER_AUTH_SECRET`.
- `src/lib/auth-client.ts`: `createAuthClient` from `better-auth/react` with `inferAdditionalFields<typeof auth>()`.
- `src/server/auth.server.ts`: `getSession` and `ensureSession` server functions. ALWAYS pass `getRequestHeaders()` to `auth.api.getSession({ headers })` — without it the session appears anonymous.
- API handler at `src/routes/api/auth/$.ts` — catch-all route mounting `auth.handler`.
- Protect routes via `beforeLoad` in `_authed.tsx` layout, never per-page.
- Set `input: false` on sensitive `additionalFields` (role, plan, …) to block client manipulation.
- After plugin changes: `bun db:auth && bun db:generate && bun db:migrate:local`.

### Zod 4

- Import from `zod/v4` — NEVER bare `zod`.
- Top-level validators: `z.email()`, `z.uuid()`, `z.url()` — NOT `z.string().email()` (better tree-shaking).
- Schema combination: `.extend()` — NOT `.merge()` (removed in v4).
- Errors: `z.treeifyError()` — NOT `.format()` or `.flatten()` (deprecated).
- `z.strictObject()` — NOT `.strict()`. Custom errors: `error` param, NOT `message`/`invalid_type_error`/`errorMap`.
- Recursive types: getter syntax, not `z.lazy()`. `z.record()` requires 2 args; `z.partialRecord()` for optional keys.
- Naming: `[Entity]Schema`, `Create[Entity]Schema`, `Update[Entity]Schema`. Inferred type: `type Entity = z.output<typeof EntitySchema>`.

### AI Gateway (the headline)

- ALL AI calls go through AI Gateway. No direct `api.openai.com` or `generativelanguage.googleapis.com` URLs in code. Reasons: caching, request/response logs, retries, cost tracking, rate limit shaping.
- Workers AI binding: `env.AI.run('@cf/meta/llama-3.1-8b-instruct', { messages }, { gateway: { id: env.AI_GATEWAY_ID } })`. The third arg pins the call to your gateway.
- Vercel AI SDK (`@ai-sdk/openai`, `@ai-sdk/google`): set the provider's `baseURL` to `https://gateway.ai.cloudflare.com/v1/<account>/<gateway>/openai` (or `/google-ai-studio`). The SDK's client objects accept a `baseURL` field on construction.
- The gateway slug + account live in env vars (`AI_GATEWAY_ID`, `CLOUDFLARE_ACCOUNT_ID`). Reference them by name; don't hard-code IDs.
- Streaming: Workers AI returns a `ReadableStream` when `stream: true` is set; pipe it directly to the response.

### Cloudflare Workflows

- One class per workflow, exported as a NAMED export from `src/entry.server.ts` so `wrangler` finds it. The class extends `WorkflowEntrypoint<Env, Params>` from `cloudflare:workers`.
- Wrap each retryable side effect in `step.do('step-name', { retries }, async () => ...)`. Each `step.do` is checkpointed — failures replay from the last successful step.
- Trigger: `await env.MY_WORKFLOW.create({ id, params })`. The `id` MUST be deterministic if the trigger is idempotent (e.g., `pipeline-${orgId}-${event.scheduledTime}`); CF rejects duplicate IDs.
- Long-running steps use `step.sleep('wait', '5 minutes')` or `step.sleepUntil('cutoff', new Date(...))`. Don't spin in a loop.

### Cron / Scheduled

- `wrangler.jsonc` lists cron expressions in `triggers.crons`. The `scheduled(event, env, ctx)` handler in `src/entry.server.ts` dispatches based on `event.cron` string match.
- Keep dispatch tiny. The scheduled handler should compare cron strings and either do a small DB query, then trigger a Workflow. Long work belongs in a Workflow, not in the scheduled handler.

### Email Sending

- Binding: `env.SEND_EMAIL` (declared in `wrangler.jsonc` under `send_email`).
- Daily quota: 1000. Sender domain must be verified in CF Email Sending. DKIM/SPF/DMARC are managed by CF.
- Wrap with a factory `createEmail({ binding, from, fromName, defaultReplyTo })` that exposes `send({ to, subject, text, html })`. Never call `env.SEND_EMAIL.send(...)` from a route directly — go through the helper so headers, reply-to, and from-name are consistent.
- For staging that shares the prod sending domain: tag `fromName` with `[Staging]` so leaked emails are obvious.

### R2

- Buckets are bindings: `env.MY_BUCKET.put(key, body, { httpMetadata })`, `.get(key)`, `.delete(key)`, `.list({ prefix })`.
- For public reads, sign URLs with HMAC over the public origin and a secret stored in CF (`ASSET_SIGNING_SECRET`). Don't expose buckets publicly.
- Keys: namespace by `<orgId>/<resource>/<filename>` so per-org cleanup is `bucket.list({ prefix: orgId })` + delete.
- The R2 SDK on the binding side returns `R2Object` (with `.body`, `.arrayBuffer()`, `.httpMetadata`). For SSR/streaming responses, return `object.body` directly.

### shadcn/ui

- `components.json` is checked in. Style: `new-york`. Base color: `neutral`. Components live in `src/components/ui/`, generated via `bunx shadcn add <component>`.
- shadcn-generated files default to default exports — `biome.json` exempts `src/components/ui/**`. Don't edit those files heavily; if you need a variant, copy and rename.
- `cn()` lives in `src/lib/utils.ts` — `clsx` + `tailwind-merge`.

### Tailwind v4

- Single CSS entry: `src/styles/app.css`. Imported once from `__root.tsx`.
- `@tailwindcss/vite` plugin handles compilation — no `tailwind.config.{js,ts}` file in v4.
- Theme tokens via CSS variables (set by shadcn's init). Custom tokens go in `@theme` blocks in `app.css`.

### Biome

- Single tool for lint + format + import sort. No Prettier, no ESLint.
- 2-space indent, 100-char width, single quotes, no semicolons, trailing commas. JSX double quotes.
- CF globals are declared in `biome.json` so `D1Database`, `R2Bucket`, etc. don't trip `noUndeclaredVariables`.
- `bun check:fix` before committing. The `auto-format.sh` hook runs it on every file edit so committed code is already formatted.

### Tests (vitest + Workers pool)

- `@cloudflare/vitest-pool-workers` runs tests inside a Miniflare-backed Worker, so `env`, D1, KV, R2 bindings work. Configure pool in `vitest.config.ts`.
- Unit tests for pure helpers can use the default vitest pool with the `cloudflare:workers` import aliased to `src/test-utils/cloudflare-workers-stub.ts`.
- D1 in tests: get a fresh in-memory database per test via the pool, run migrations once in `beforeAll`.
- Test behavior, not implementation. No snapshot tests. Mock at boundaries (external HTTP), not internals.

## Anti-Patterns (Do NOT)

- Don't read `process.env` from worker code. Use `import { env } from 'cloudflare:workers'`. The only `process.env` lookup that's OK is in `vite.config.ts` for build-time switches like `WRANGLER_ENV`.
- Don't hand-write `wrangler.jsonc` secret values. Use `wrangler secret put NAME` or the dashboard. `vars` in `wrangler.jsonc` are PUBLIC at runtime — never put a key there.
- Don't hand-edit `drizzle/migrations/*.sql`. Run `bun db:generate` from a schema change.
- Don't hand-edit `worker-configuration.d.ts` or `routeTree.gen.ts`. Both are generated.
- Don't bypass AI Gateway. No direct provider URLs in code; route through the gateway baseURL or the `gateway` option on `env.AI.run`.
- Don't use `useEffect` for data fetching. Server functions + TanStack Query.
- Don't use `useState` for server state. Server functions + TanStack Query.
- Don't use bare `zod` import — always `zod/v4`.
- Don't use `.merge()` (Zod 4 removed it). Use `.extend()`.
- Don't use `.format()` / `.flatten()` on `ZodError`. Use `z.treeifyError()`.
- Don't use default exports outside route files and config files.
- Don't use `React.FC` or `React.FunctionComponent`.
- Don't put `tanstackStartCookies()` anywhere but LAST in the better-auth plugins array.
- Don't call `auth.api.getSession()` without `getRequestHeaders()` — session will appear anonymous.
- Don't trigger Workflows with non-deterministic IDs when the trigger is idempotent (cron, retried webhook). CF rejects duplicate IDs — that's the feature.
- Don't run `wrangler d1 execute --remote` without confirming with the user. It hits production.
- Don't put work in the `scheduled` handler. Dispatch a Workflow and exit.
- Don't import `cloudflare:workers` from route components — Vite will bundle worker code into the client. Use server functions or move the call into `src/server/...`.
- Don't suppress Biome with `// biome-ignore` without a comment explaining why.
- Don't create barrel `index.ts` re-exports — import directly so the bundler can tree-shake.

## Error Handling

- TanStack Router: `errorComponent` per-route for runtime errors, `notFoundComponent` for 404s, `notFound()` in loaders.
- Server functions: throw `Error` for failures. The framework serializes; the client sees a thrown promise. For typed expected failures, return a discriminated union.
- Workflows: failures inside a `step.do` retry. Wrap external calls in `step.do` so they replay; wrap purely deterministic computation outside steps.
- D1: errors propagate as exceptions. Catch at the call site only when you have a fallback.
- Don't swallow errors. Log via `console.error` (Workers Logs ingests it) — never `try { ... } catch {}`.

## Customization

The kit ships only configuration. Most projects add bits over time:

- New library? Update the **Tech Stack** table and add a section to **Coding Conventions** explaining the rule.
- New binding? Add it to `wrangler.jsonc`, run `bun cf-typegen`, then surface the access pattern as a one-liner in **Cloudflare Bindings**.
- New convention? Append an anti-pattern to **Anti-Patterns** with the reason.

The kit's slash commands (`/setup`, `/add-d1-table`, `/add-ai-route`, `/add-workflow`, …) read this file before generating code, so keep it accurate. If you find Claude generating code that breaks a convention, the file is wrong, not Claude.
